## Day 0 · 11/10（周二，剩 ~6h）

### 任务

| # | 任务 | 时长 | 验收标准 |
|---|---|---|---|
| 0.1 | `git init` + 首次提交骨架 | 0.5h | `git log` 有 `feat: initial skeleton` |
| 0.2 | 申请并配置 LLM API Key（DeepSeek/通义/智谱任一） | 0.5h | `echo $env:LLM_API_KEY` 有值，且 `.env` 已被 gitignore |
| 0.3 | 跑通 `--planner llm` 的 5 条 easy 场景 | 2h | 能看到真实模型的 tool_calls 轨迹 |
| 0.4 | 全量 24 条跑真实模型，记录基线 | 2h | `docs/BASELINE.md` 有数字 |
| 0.5 | 把失败案例抄进 BASELINE 的 Failures 段 | 1h | 至少 3 条失败归因 |

### 交付物

- `docs/BASELINE.md`（**第一版真实指标**，后面所有优化都跟它比）
- commit：`feat: initial agent skeleton` / `docs: add baseline metrics`

### 卡点预案

- **API 调用报 401/超时**：先改用 `--planner oracle` 确认链路没问题，再单独排查 key/网络；别在环境上耗超过 1 小时。
- **模型不按格式返回 tool_calls**：把 `temperature` 设 0，`tool_choice="auto"`；必要时先在 prompt 里给一个 few-shot 示例。

## Day 1 · 11/11（周三，8h）：混合检索

### 任务

| # | 任务 | 时长 | 验收标准 |
|---|---|---|---|
| 1.1 | 给 runbook 建向量索引（API embedding 或本地 TF-IDF 兜底） | 2h | 同一 query 能召回 3 篇，含正确答案 |
| 1.2 | 实现 RRF 融合（BM25 排名 + 向量排名） | 1.5h | `search_kb` 新增 `mode=hybrid` 参数 |
| 1.3 | 实验 A：`bm25` vs `vector` vs `hybrid` | 2h | 三种模式各跑 24 条，出对比表 |
| 1.4 | 把对比表写进 `experiments/A_retrieval.md` | 1h | 含 Recall@3 与任务成功率 |
| 1.5 | 八股/手撕 30 分钟 | 0.5h | Redis 缓存三兄弟 + 1 道 LRU |
| 1.6 | 提交 | — | `feat: add hybrid retrieval with RRF` / `docs: retrieval experiment` |

### 验收数字

- 至少一项指标提升，或**明确写出"混合没有提升，因为语料太小"**——后者也是合格的实验结论。
- Recall@3 的定义与计算脚本要能复现。

### 卡点预案

- 没有 embedding API：用 `hash(tf-idf)` 做伪向量，先跑通链路，在文档里标注"伪向量，仅验证管线"。
